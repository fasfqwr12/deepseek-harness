# @deepseek-ai/dsh-client-client-errors

[English](README.md) | 中文

浏览器异常上报。shell 启动内核（`@deepseek-ai/dsh-client-web`）持有页面的 `error`、`window.onerror` 与 `unhandledrejection` 监听器——即使插件加载失败它们也必须运行——并把每次失败以一条 JSON 报告 POST 到 `/client-errors/report`。本包持有该端点字面量及其宿主侧：路由把请求体限制在 `maxBodyBytes`（超出返回 413）、忽略任何不是报告的内容、把 `stack` 截断到 2000 字符、`ua` 截断到 200 字符、每分钟只接纳 `reportsPerMinute` 条（每个超限窗口只警告一次），并把每条被接纳的报告记录为一条 `client-error:` 警告。所有结果都返回空的 204，因此页面代码无法区分「报告被接纳」与「报告被拒绝」。浏览器侧还有自己的边界：重入保护（同一时刻只允许一条报告在途）、按 kind + message + source URL 的 5 秒去重，以及每分钟 20 条的预算。

## 模型体验

无。该通道属于浏览器侧诊断机制；这里没有任何内容进入模型请求。

#### KV Cache 影响

无；该包（package）既不组装也不发送提供方请求。

## 已知限制与暂缓事项

- **端点不做鉴权**：它与其他 Web 表层一样位于浏览器信任栅栏之后，而报告的唯一效果是写一行宿主日志；若要求鉴权，则恰好在页面坏到无法鉴权时上报失效。
- **报告会被截断与限流**：超过 `maxBodyBytes` 的报告、超过 2000 字符的 stack、或超出 `reportsPerMinute` 的页面会被截断而不是缓存，因此失控页面无法把诊断通道变成第二次故障。
- **去重只在浏览器侧**：宿主看不到页面从未发出的重复失败，因此当客户端丢弃报告（重入、去重、预算）时，宿主侧不会留下该丢弃的任何痕迹。
